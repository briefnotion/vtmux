# vtmux

スライドとフェードの切り替え効果を持つ端末マルチプレクサです。コンソールで `vtmux` を起動すると、見た目はこれまでと同じコンソールですが、下に1行だけ
コントロールバーが加わります。すべてこれまでどおりに動きます。`Ctrl-B` を押すとバーの色が変わり、コマンドモードになります。ここではコロンに続けてコマンドを入力して
コンソールを作ったり閉じたりでき、左右の矢印キーでコンソールを切り替えることもでき、画面は
スライド（またはフェード）して入れ替わります。

![vtmux](docs/demo_sheet.png)

*実際のプログラムを動かしている vtmux。バーは下端にあります。上：2番目のコンソールで動く [vtweather](https://github.com/briefnotion/vtweather) のレーダー地図。
`Ctrl-B` を押した状態です（バーが琥珀色になるのがコマンドモード）。左下：4番目のコンソールで動く vtshow の雷雨シーン。
右下：中国語のテキスト（生日快乐、「お誕生日おめでとう」）を表示するチャットプログラム。2桁幅で描かれています。*

描画ライブラリ [vtscreen](https://github.com/briefnotion/vtscreen)（vtshow や vtweather と同じもの）の
保持型ピクチャの上に作られています。動きのないコンソールは、描画にほとんどコストがかかりません。内部の端末エミュレータ（`src/emulator.*`）は新規に書かれたもので、
ステートマシン方式のパーサーとメモリ上の画面からなり、`tmux` と `pyte` に対してテストされています。

## ビルドと実行

Linux、C++17 対応の `g++`、`cmake` 3.16 以降、`git`：

    git clone --recursive --shallow-submodules --depth 1 https://github.com/briefnotion/vtmux.git
    cd vtmux/build
    ./m
    ./vtmux

`./m`（`build` ディレクトリ内）は vtmux をビルドし、変更後には再ビルドします。クローンをサブモジュールなしで作った場合は `vtscreen` サブモジュールも取得し、
`cmake` やコンパイラがなければ知らせてくれます。`./m test` はテストもビルドして実行し、`./m clean` はビルドしたものを削除します。

`./install`（これも `build` 内）は `./m` を実行してから `vtmux` を `~/.local/bin` にコピーするので、どのプロンプトからでも `vtmux` と入力できます（root で実行した場合は `/usr/local/bin`）。
`./install --system` は全員向けに `/usr/local/bin` に置き（sudo を求めます）、`./install DIR` は `DIR` に置き、
`./install --remove` は取り除きます。そのフォルダが `PATH` に入っていなければ、そう知らせて追加すべき行を表示します。

`./m` を手でやる場合：`cmake -B build && cmake --build build`。`-DVTMUX_TESTS=OFF` でテストのビルドを省略できます。

    vtmux [--transition slide|dip|dissolve|crossfade] [--transition-ms N] [--no-color] [--no-images] [--fps N] [-- command args ...]

コマンドを指定しないと、最初のコンソールはシェル（`$SHELL`）を実行します。中で動くプログラムは `TERM=xterm-256color` で動きます。

## キー

通常モードでは、すべてのキーがそのままコンソール内のプログラムに渡されます（Ctrl-C や Ctrl-Z も）。監視しているキーは `Ctrl-B` だけです。

| コマンドモード（`Ctrl-B` の後）で | 動作 |
|---|---|
| `Left`, `Right` | 前の／次のコンソールへ、切り替え効果つきで（コンソールの列に沿ったスライド。最後のコンソールから `Right` を押すと、最初まで一気に戻るようにスライドします）。コマンドモードのままなので、続けて切り替えられます |
| `1` ～ `9` | そのコンソールへ移り、通常モードに戻ります |
| `c`, `n`, `p` | 新しいコンソール、次、前（tmux と同じ） |
| `Up`, `Down`, `PageUp`, `PageDown`, `Home` | コンソールの履歴（2000行）をさかのぼって見ます。バーにどこまで戻ったかが表示されます。`End` でライブ画面に戻ります |
| `:` | コマンドを入力します（Enter で実行、Esc でやめる、Backspace で修正、Ctrl-U で消去） |
| `Esc`, `Enter` | 通常モードに戻ります（ライブ画面にも戻ります）。コンソールに入力しても同じです |
| `Ctrl-B` | 本物の Ctrl-B をプログラムに送り、通常モードに戻ります |

## スライド

コンソールはバーの順に横一列に並んでいます。切り替えると、その列に沿って表示がスライドするので、2つの画面が途中まで同時に見え、
複数のコンソールを飛び越えるときは間にあるものが通り過ぎるのが見えます。スライドの途中でキーを押すと、そのときの表示位置から次のスライドが始まります。
新しいコンソール（`new`）は表示中のコンソールの右隣に、2段階で入ります。まず古いほうが左へ滑り出て空白（ボイド。既定では暗い青）を残し、次に新しいほうが上から落ちてきます。閉じるときも2段階です。閉じたコンソールが下へ落ち、次にその左隣（最初のものを閉じたなら次のもの）がスライドして入ってきます。この2段階を合わせると、1段階の1.5倍の時間がかかります。バーは動かず、
カーソルはコンソールが着地してから描かれます。すべて時計で時間管理されているので、遅い端末ではコマが飛びますが、スライドにかかる時間は変わりません。

## コピーと貼り付け

- 通常のコンソール（一覧表示やシェル）では、いつもどおりマウスで選択します。それは端末プログラムがやることで、vtmux は邪魔しません。
- 自分でマウスを使うプログラム（micro、btop、`mouse=a` の vim）には代わりにマウスイベントが渡るので、ドラッグするとプログラム内で選択されます。
  端末プログラム自身の選択を使うには、ドラッグ中に `Shift` を押し続けます（Windows Terminal、ほとんどの Linux 端末）。
- 自分でコピーするプログラム（設定で `"clipboard": "terminal"` にした micro、vim や tmux 風のプラグイン、スクリプトからの `printf`）は、
  テキストをエスケープシーケンス（OSC 52）で端末に送り、端末プログラムがクリップボードに入れます。vtmux は表示中のコンソールからのものを
  そのまま通すので、micro での Ctrl-C は vtmux なしのときと同じように動きます。バックグラウンドのコンソールはクリップボードを設定できません。
  通すのは書き込みだけで、プログラムが vtmux 経由でクリップボードを読むことはできません。`:set clipboard off` ですべて止まります（既定はオン）。
  端末プログラム側にも、このための切り替えがあるかもしれません。
- 貼り付けは貼り付けとして渡されます（プログラムが求めれば、ブラケット付きで）。

## 画像（Sixel）

お使いの端末が Sixel 画像を描画できるなら、コンソールの中のプログラムは端末そのものと同じように画像を描け、画像は文字と同じように振る舞います。
（Windows Terminal で試しています。下の2つの問いに答える端末なら使えるはずです。）

起動時に vtmux は端末に2つのことを尋ねます。Sixel を描画できるか、そして文字セル1つが何ピクセルか。尋ねるのは
[vtpen](https://github.com/briefnotion/vtpen) で、vtmux が画面を引き継ぐ前に行います。少し時間がかかり、端末が全く応答しないときは最大1秒です。その間に入力した
内容は失われません。その後、コンソールには本当のことが伝えられます。デバイス属性は端末が対応しているときだけ Sixel を名乗り、セルとウィンドウのサイズ（`CSI 14 t`、`16 t`、`18 t`。疑似端末のウィンドウサイズにもピクセルが入ります）、色数と最大の画像（256色、4096×4096ピクセル）にも答え、`XTVERSION` は
`vtmux` と答えます。Sixel プログラムのように先に調べるプログラムは、これで正しく動きます。

画像の振る舞い：

- 画像は、覆う文字セルごとに1つの断片に切られ、断片はそれぞれのセルについて回ります。画像は文字と一緒にスクロールし、行と一緒に履歴に入り、履歴をさかのぼると見えます。
- セルの上に文字を書くと、そのセルの画像の断片は消えます。消去や、文字・行の挿入・削除は、断片をセルと一緒に消したり動かしたりします。代替画面（vim、less）には
  専用の画像があります。`ESC [ 3 J` は履歴の画像を消し、完全リセット（`reset`）は画面上の画像を消します。
- 画像のあと、カーソルは画像の下の行、画像が始まった列に来て、必要なら画面がスクロールします（xterm や DEC 端末と同じです）。モード 8452 を設定すると、
  カーソルは画像の最後の行の、画像の右に残ります。モード 80（DECSDM）を設定すると、画像は画面の左上から始まり、スクロールはせず、収まらない部分は切り捨てられ、
  カーソルは元の位置のままです。
- 画像はトランジションでもコンソールと一緒に動きます。スライドは画像を動かし、クロスフェードはピクセルを溶かし、ディゾルブは各セルのピクセルをその文字と
  一緒に切り替え、ディップは暗くします。ヘルプカードは画像の上に描かれ、画像はそのまわりに見えます。

制限：

- 画像は4096×4096ピクセル・256色まで（大きいものは切り捨て）、Sixel のテキストは32 MiB まで（それを超えると画像ごと捨てられます）。
- コンソールごとに64 MiB の画像を保持します（1ピクセル4バイト）。いっぱいになると、もうどこにも表示されていない画像から、次に古いものから消えます。履歴の中に
  あっても同じです。保持できないほど大きい画像は表示されませんが、画面上の場所は取ります。
- セルの大きさは起動時に1回だけ尋ねます。そのあとフォントサイズを変えたら、vtmux を再起動してください。
- カーソルは画像の上には描かれません。

端末が Sixel を描画できないとき、`vtmux --no-images` で起動したとき（`VTMUX_NO_IMAGES` を設定した場合や `--no-color` の場合も同じで、色がなければ画像もありません）は、
プログラムには Sixel がないと伝えられ、それでも送られてきた画像は捨てられて場所も取りません。vtmux が2つ目のサブモジュール vtpen なしでビルドされた場合も同じです
（`git clone --recursive` で取得できます）。その場合 vtpen は単に使われません。

## コマンド（コロンの後）

| コマンド | 動作 |
|---|---|
| `new [name] [-- command ...]` | シェル（またはそのコマンド）を実行する新しいコンソールを作り、そこへ移ります。`new "my name"` は空白を保ちます |
| `close`, `kill` | このコンソールを閉じます（プログラムには hangup が送られます）。最後の1つを閉じると vtmux を終了します |
| `next`, `prev`, `goto N` | 切り替え効果つきで切り替えます |
| `rename NAME` | このコンソールにバー上の名前を付けます |
| `list` | コンソールの一覧をしばらくバーに表示します |
| `set transition slide\|dip\|dissolve\|crossfade` | 切り替えの見た目：`slide`（既定）は画面を横に並べてスライドさせ、間のものを通過させます。`dip` は古い画面を暗くフェードアウトさせてから新しい画面を明るく戻します。`dissolve` はセルごとに入れ替えます。`crossfade` は vtshow と同じように色を混ぜます。（`set fade` も引き続き使えます） |
| `set transition-ms N` | 1段階にかかる時間、0～5000（既定は1000。0 なら即座に切り替え）。複数のコンソールにわたるスライドは少し長くかかり、最大2倍までです |
| `set void-color RRGGBB\|off` | コンソールを開く／閉じるときの空白部分の色（既定は `101220`。`off` なら端末自身の背景のまま） |
| `set clipboard on\|off` | プログラムがクリップボードを設定してよいか（OSC 52、「コピーと貼り付け」参照。既定はオン） |
| `set fps on\|off` | 測定したフレームレートをバーに表示します（既定はオフ）。`--fps N` は1秒あたりの最大フレーム数を決めます（既定は60） |
| `quit` | すべて閉じて終了します |
| `help` | 画面の中央（約3分の2の大きさ）にすべてのキーとコマンドを載せたカードを表示します。コンソールはその周りで動き続けます。画面が小さくて全部入らないときは `Up`, `Down`, `PageUp`, `PageDown`, `Home`, `End` でスクロールでき、`Enter`, `Space`, `Esc`, `q` で閉じます |

プログラムが自分で終了した（`exit` と入力した）コンソールは閉じます。最後の1つが閉じると vtmux は終了し、端末は元の状態に戻されます。

## 仕組み

[DESIGN.md](DESIGN.md) を参照してください。要点：各コンソールは疑似端末上のプログラム（`Session`）で、読み取りスレッドが
`Emulator` にデータを渡します。UI スレッドは変更のあった行だけを保持型の vtscreen `Picture`（`PanePainter`）に描き、2つのピクチャを混ぜて
フェードを作り（`blend`）、バーを描いて結果を表示します。通常モードの入力バイトはそのままプログラムへ渡ります。そのとき本物の端末は
プログラムが期待するとおりにキーを送らなければならないため、vtmux は表示中のコンソールの入力モード（アプリケーションカーソルキー、ブラケット付き
貼り付け、マウス、フォーカス）に端末を切り替え、終了時に元に戻します。

Sixel 画像は文字セルごとに1つの断片に切られ、文字の隣の画像レイヤー（`src/pictures.h`）に保持されます。レイヤーはセルに起こることすべてに追従します。
ペインターは断片をピクセルとして vtscreen に渡し（`Picture::place_image`）、トランジションがそれを運びます。

## まだできていないこと

- 太字、斜体、下線、取り消し線、点滅は通常のコードとして端末に送られ、幅の広い文字（中国語、絵文字）は2桁を使います。見え方、あるいは
  表示されるかどうか（点滅と斜体は表示されないことがよくあります）は、端末プログラム次第です。結合文字は
  捨てられ、エミュレータの表と異なる幅で端末が描く文字は、おかしく見えることがあります。
- デタッチ／アタッチなし（サーバーがないため）、分割画面なし、コピーモードなし（履歴は見られますが選択はできません）、マウスコマンドなし、設定ファイルなし。
- エミュレータが未対応のもの：倍幅・倍高の行（`ESC # 3` ～ `6`。無視されます）、結合文字（
  捨てられます）。80/132 桁の切り替え（DECCOLM）はペイン内で機能します。下記参照。
- 画像：Sixel を表示できない端末のための代替描画はなく、他のグラフィック言語（ReGIS）は理解せず、セルの大きさは起動時に1回だけ尋ねます。

## テスト

- `tests/run_tests.sh` はすべての単体テスト（`tests/*_tests.cpp`。それぞれが `// sources:` の行で自分のソースを示します）を厳格な警告
  フラグとアドレスおよび未定義動作サニタイザ付きでビルドして実行します。対象はパーサー、エミュレータ、キーパーサー、ペインター、
  フェード、セッション（本物の疑似端末上の本物のプログラム）、アプリ（モード、コマンド、フェード。バイト列と作り物の時計で駆動）です。`ctest --test-dir build` は CMake ビルドから同じテストを実行します。
- `tests/e2e/run.sh` は疑似端末の中で本物の `vtmux` を本物のプログラム（`less`、`vi`、`top`、`htop`、Ctrl-C と
  Ctrl-Z、サイズ変更、モードの反映、素早い切り替え、大量出力、アイドル時の CPU）とともに実行し、端末エミュレータで画面を読み戻します。
- 画像には専用のテストがあります。`tests/pictures_tests.cpp` は、画像を保持するエミュレータと、その代わりに文字を保持するエミュレータにランダムな入力を流し込み、
  断片に起こることが文字に起こることと同じであるか（上書き、消去、スクロール、履歴、もう一方の画面）を確かめます。`tests/render_pictures_tests.cpp` は
  ペインターが vtscreen に渡すピクセルをエミュレータの保持するものと照合します。トランジションとヘルプカードも画像つきでテストし、エンドツーエンドのテストでは、
  Sixel 画像を描くプログラムを、描ける模擬端末と描けない模擬端末で実行します。
- `tests/conformance/run.sh` は、生成した何千ものエスケープシーケンスの流れ、手書きの画面、本物のプログラムのキャプチャを
  エミュレータ（`tools/vtdump.cpp`）、tmux、pyte に与え、画面を比較します。`tests/vt100_tests.cpp`、`vt102_tests.cpp`、`vt52_tests.cpp` は
  DEC 端末の振る舞いを固定します。見つかったことは `tests/conformance/FINDINGS.md` にあります。
- 本物の `vttest`（`sudo apt install vttest`）を試すには、vtmux の中で実行します。vttest はモード40で許可したうえで
  DECCOLM により画面を80（または132）桁に切り替えます（xterm が要求するとおり）。vtmux はこれをペイン内で行います。画面は左側の80桁幅になり
  （ペインが十分広ければ132。それより狭いペインは幅をすべて使います）、ペインの残りは空白のままで、プログラムには新しいサイズが伝えられ
  （SIGWINCH）、画面は消去されます。完全リセット（`reset`、`ESC c`）、モード40の解除、ウィンドウのサイズ変更でペイン全体が戻ります。
  モード40がなければ切り替えは画面を消去するだけなので、`reset` コマンドで幅が狭くなることはありません。vttest の倍幅の行は
  倍幅では描かれません（上記参照）。
- `tools/demo.py` は疑似端末から vtmux のスクリーンショット一式を作ります。`tools/preview_transition.py` は3種類のフェードを描画します。
